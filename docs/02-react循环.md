# ReAct 循环

## 核心思想

ReAct 是 Reasoning 与 Acting 的结合。传统做法是让模型一次性输出答案，一旦需要外部信息或计算就无从下手。ReAct 把一次回答拆成多轮：模型先判断当前信息够不够，不够就发起一次行动（调用工具），拿到观察结果后再判断，如此循环直到能给出答案。

循环的四个动作是 Reason（思考）、Act（行动）、Observe（观察）、Repeat（重复）。关键在于：下一步做什么不是代码写死的，而是模型根据上一步的观察结果自己决定的。

## 在代码里怎么落地

agent.py 的 chat 方法里有一个 for 循环，上限是 max_steps，默认 10。每一轮做三件事：把当前 messages 发给模型，把模型返回的 assistant 消息原样追加回 messages，然后检查有没有 tool_calls。

如果没有 tool_calls，说明模型认为可以收尾了，直接返回 content。如果有 tool_calls，就逐个取出函数名和参数，在本地执行，再把结果以 role 为 tool 的消息追加回 messages，带上对应的 tool_call_id，进入下一轮。

## 两个容易踩的坑

第一，assistant 消息必须原样回填，包括 tool_calls 字段。如果只回填 content，下一轮模型就看不到自己刚才请求了什么，会重复调用同一个工具，形成死循环。

第二，tool 消息必须带 tool_call_id，且要与某个具体的调用一一对应。模型一次可能并行请求多个工具，少了这个字段协议就对不上，接口会直接报 400。

## 为什么要 max_steps

模型有可能陷在循环里出不来，比如工具反复返回「没查到」，它就一直重试。这不仅是体验问题，还会持续消耗 token 和余额。max_steps 是一道硬性安全阀，走满就强制停止并返回一句提示，把问题交回给用户拆解。

这是工程上很典型的一笔账：宁可少答一次，也不能让一次请求无上限地烧钱。
