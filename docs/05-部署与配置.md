# 部署与配置

## 本地启动

必须用 streamlit run app.py 启动，不能用 python app.py。app.py 里全是 Streamlit 的 API 调用，直接用 python 执行会因为没有运行时上下文而只输出一堆 missing ScriptRunContext 警告，然后进程直接退出，什么服务都不会启动。

启动前确认虚拟环境已激活，终端提示符前面有 .venv 前缀。如果 streamlit 命令找不到，用 .venv/Scripts/python.exe -m streamlit run app.py 等价写法绕过 PATH 问题。

## API Key 管理

需要两个 Key：DEEPSEEK_API_KEY 用于对话，ZHIPU_API_KEY 用于向量化。本地放在项目根目录的 .env 文件里，这个文件已经在 .gitignore 中，不会被提交。

app.py 里的 _get_key 函数做了双模式读取：先查环境变量，没有再去读 Streamlit 的 st.secrets。这样同一份代码在本地和云端都能跑，不用改任何东西。两个 Key 必须在导入知识库模块之前注入环境变量，因为 knowledge.py 在导入时就会初始化客户端。

## 云端部署

推送到 GitHub 之后，在 share.streamlit.io 新建应用，指向仓库的 main 分支和 app.py。然后在 App settings 的 Secrets 里填两个 Key，格式是 TOML 的键值对。保存后会自动重新部署。

要注意的是 Streamlit Cloud 每次推送都会自动重建，所以推代码之前最好本地先跑一遍。另外云端文件系统是临时的，.cache 目录不会跨重启保留，冷启动需要重新向量化一次，这也是为什么要尽量控制块的数量。
